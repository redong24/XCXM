## 2. Phase 1 · Design Read（一句话）

> **Design Read：** 把它读作**一款消费级、全天候在岗的医疗哨兵型移动产品 UI**，服务于**一个成人（家长或患者本人）同时看护 1-N 个孩子的哮喘风险**，语言是**冷静、高可信、3 秒内可读懂的「仪表」语言**，方向倾向**克制的现代医疗风，Linear / Stripe 的结构严谨性 + 临床监护仪的可读性，而不是消费级运动手环的游戏化，也不是 CGM 那种深色驾驶舱**。

三条推导：
1. **"哨兵"决定信息架构**。首页第一个问题不是"我今天数据好不好"，而是**"现在有事吗？哨兵还活着吗？"** → 首屏必须同时回答风险等级 + 数据新鲜度。
2. **"消费级 + 多孩"决定导航**。家长在 2 个孩子间切换必须是 1 次点击，不能藏在设置里。
3. **"预警优先"决定视觉预算**。全应用其余部分越安静，红色预警越刺眼。**红色是全局保留色，除真实红区外任何地方不得出现。**

## 3. Phase 2 · CALIBRATE（三个 dial + 基础）

基线是 `8 / 6 / 4`。本项目**全部低于基线**，这是刻意的：

```
DESIGN_VARIANCE : 3   (基线 8)
MOTION_INTENSITY: 3   (基线 6)
VISUAL_DENSITY  : 4  首页 / 6  预警详情 + 报警设置
```

**DESIGN_VARIANCE = 3**，这是报警仪器。凌晨 3 点，非对称和惊喜都在消耗识别速度。variance 只花在**一个地方**（§4 的 signature），其余一律规整。

**MOTION_INTENSITY = 3**，动画只允许三种理由：
- (a) 哨兵条标记的**呼吸脉动**＝每次成功上传脉动一次，**证明数据是活的**（这是功能，不是装饰）
- (b) 安全区 / 关注区 / 红区之间的**状态换肤过渡**
- (c) 按钮 `:active` 的触觉反馈

技能规定「若声称 MOTION > 4，页面必须真的在动」。我声称 3，因此**不会**出现视差、入场序列、滚动触发动画。

**VISUAL_DENSITY 分面声明**，首页 4（可瞥读优先），**预警详情与报警设置 6**。依据来自竞品实证：Sentinel CGM Monitor 的 12 张商店截图里**有一半是报警配置**（per-user 设置、Ninja Alarm 自动小睡、Night Mode 起止小时、手机 / 手表分别设定、TEST HAPTIC / TEST SOUND）。**报警类产品的密度就该堆在报警配置页**，而不是首页。这一条我们照抄结构，不照抄它的视觉。

### 基础（Foundation）

技能要求「若能映射到真实设计系统就装官方包，绝不手抄它的 CSS」。**本项目无法映射**：
- uni-app x / uvue 在 Android 端**走原生渲染**，不是浏览器
- **没有 Tailwind、没有 shadcn/ui、没有 Radix**
- **只支持 flex 布局，没有 CSS Grid**；不支持 `dvh`；不支持后代 / 组合选择器；不支持大部分伪类

因此基础是：**手工 token 层**，落在 `uni.scss`（CSS 变量 + 类）+ `styles/tokens.uts`（UTS 侧需要读取的同一批值，避免两处漂移）。**一套系统，不混第二套。**

## 4. Phase 2.5 · Token 计划 + 「同质化自我攻击」

### 4.1 先做自我攻击（技能强制）

技能列出 AI 设计的三种默认长相：
1. 暖米白 `#F4F1EA` + 高对比衬线 + 赤陶色点缀
2. **近黑底 + 单一酸性绿 / 朱红点缀**
3. 报纸式发丝分割线 + 零圆角 + 专栏排版

**我的第一反应正是第 2 种**（深色底 + 荧光绿），而这恰好**就是 Sentinel CGM Monitor 的长相**（黑底 + `#1E1E1E` 深灰卡 + 亮柠檬绿 + 未来感窄体）。用一个类似的 prompt 重新推导，我会落到同一个地方 → **说明它不是从这个 brief 推出来的，是默认值。必须改。**

**改了什么、为什么改：**

去技能要求的「主题自身的世界」里找锚点。这个主题的世界是**呼吸和空气**，它的器物是：峰流速仪（一根带绿 / 黄 / 红分区的刻度）、指夹血氧仪、流量-容积环、雾化器，以及，

> **哮喘行动计划卡（Asthma Action Plan card）：一张贴在冰箱上的、印着绿 / 黄 / 红三个分区的纸卡。**

这是哮喘家庭**真实拥有、并且已经会读**的实物，也是国际标准做法（GINA）。**它就是本设计的 ground truth。** 这个锚点是主题特有的，不是任何一种默认审美。

由此得到第二个反默认决定：**浅色为主，不是深色为主。**
- 家长白天用它，冷静可信；
- **凌晨的预警屏应当是全应用唯一的深色 / 高饱和界面**，这样它不可能被认错，把对比度花在真正重要的地方；
- 中国消费级健康市场里，浅色读作"医疗可信"，深色读作"黑客 / 加密货币"。

### 4.2 Color（6 个命名值 + 3 个分区色）

```
--paper       #F7F8F7   极浅冷绿白（不是米白 #F4F1EA，不是纯白）
--ink         #14181A   近黑（不是 #000000）
--ink-2       #5A6468   次级石板灰
--hairline    #E2E6E4   发丝线
--accent      #2C6E8F   克制的临床蓝青（饱和度 ~53%，唯一强调色）

分区色（源自行动计划卡，降饱和到医疗观感）
--zone-green  #1F8A5F   安全区
--zone-amber  #C9821B   关注区
--zone-red    #C43A2F   红区（全局保留）

预警换肤
--alert-bg    #2A1210   深氧化红（不是黑）
--alert-fg    #FFF4F2
```

关键约束：
- **`--accent` 与任何分区色都不同**，所以普通按钮永远不会被误读成报警。
- **Colour Consistency Lock**：`--accent` 在 10 个页面里完全一致。
- **Theme Lock**：应用只有一个主题；**唯一的例外就是 signature（§4.5），换肤本身即报警语义**。

### 4.3 Type（角色 ≥ 2）

平台诚实约束：Android 端只有系统字栈可靠（Noto Sans CJK / 思源黑体）。技能禁用 Inter / Roboto 作默认，这条按 web 假设写的；在这里的正确解法是**只为数字打包一个字体**：

| 角色 | 字体 | 理由 |
|---|---|---|
| metric（数字） | **IBM Plex Mono**，仅子集化数字 + 符号（OFL，≈15KB） | **等宽数字（tabular figures）**：心率从 98 跳到 101 时数字不会左右抖动。这是功能理由，不是审美理由 |
| body（中文正文） | 系统 CJK 字栈 | 唯一可靠、零体积、正确的中文字形 |
| utility（说明 / 时间戳） | 同 body，更小字号 + 更宽字距 | 不引入第三个字族 |

不使用衬线体。技能：衬线只在真正的编辑 / 奢侈 / 传承类项目里成立，医疗监护不是。

### 4.4 Layout（一句话 + ASCII 线框）

一句话：**每一屏从上到下回答一个递进的问题，"是谁 / 有事吗 / 数据新不新 / 现在做什么 / 过去怎样"，用发丝线分层而不是卡片堆叠，卡片只在"抬升确实表达层级"时出现。**

`flex` 唯一可用 → 严格 `flex:1` + 固定 px，**绝不用百分比数学**（保留技能 C19 的意图，虽然它的原文针对 CSS Grid）。

### 4.5 Signature（唯一的记忆点）

> **「哨兵条」（The Sentinel Bar）**
>
> 首页顶部一条横向的行动计划分区带，把当前看护对象的实时风险映射到**家长本来就认识的绿 / 黄 / 红纸卡**上。一个细标记指示当前位置，**每次成功上传脉动一次**（活性证明），下方一行发丝字给出「上次上传 12 秒前」。进入红区时，**整屏换肤**、标记锁定在红端。

它**替代**了首页原有的「三张等宽指标卡」，技能明确禁止 three-equal-feature-cards 这个排布。

**交付前移除一个配件**（技能强制）：**删掉首页的 HRV 卡**。后端 `alert_engine.hrv` 直接 `return AlertDecision(False)`，HRV 根本不参与预警，界面上常年显示 `--`，这是在消耗信任。删。

### 4.6 Finish gate 预答

> 把 logo 换成另一家公司的，这个界面还会像那家产品吗？

不会。哨兵条 + 数据新鲜度作为一等公民 + 红色全局保留 + 唯一深色屏就是报警本身，这四条捆在"哮喘家庭的行动计划卡"上，换不到别的产品身上。

### 7.3 哨兵的生死线：离线推送

这一条我必须单独讲，因为它直接决定产品承诺能不能成立。

> 官方原文加粗：**「若未完成开通离线厂商推送，只有在 app 在线时才能收到消息」**

「app 在线」= 应用在前台运行。而**哮喘发作最危险的时段是凌晨 2-5 点**，那时手机锁屏、app 进程大概率已被系统回收，**正是"不在线"的状态**。

也就是说：

- **只开在线推送 = 哨兵只在你盯着屏幕时值班。** 这等于没有哨兵。
- **离线厂商推送是本产品的必选项，不是优化项。**

所以推送不是一个「加个功能」的事，它有一条完整的前置链：

```
创建应用拿真 appid
   ↓
开通 uni-push 2.0
   ↓
生成固定签名证书（.keystore），  华为要 SHA256 指纹且必须与云打包证书一致
   ↓
逐厂商配置离线推送（华为/荣耀/小米/OPPO/vivo）
   ↓
申请消息分类（否则单日 2 条上限，第 3 次预警静默丢失）
   ↓
云打包（自定义基座）→ 拿到真 cid → 查 Device Token 验证离线链路
```

开发期可先用**华为 / 荣耀 / 魅族 / OPPO 测试环境**（不要求上架）打通并验证；**小米 / vivo / OPPO 正式**要等上架应用商店。

### 7.4 消息分类必须申请（否则哨兵会被厂商静音）

默认按「营销类」限流 → **单应用单设备单日 2 条**。一个哨兵产品一天被限 2 条预警是荒谬的。

按官方 `options` 规范，预警消息应声明为**服务与通讯类**：

```jsonc
"category": { "harmony": "EXPRESS", "huawei": "EXPRESS", "vivo": "ORDER" },
"options": { "android": {
    "HO": { "/android/notification/importance": "NORMAL" },  // 服务与通讯类
    "XM": { "/extra.channel_id": "<小米申请的渠道id>" },        // 不传会被小米拦截
    "OP": { "/category": "<Opush类别>", "/notify_level": 16 }  // 通知栏+锁屏+横幅+震动+铃声
}}
```

`notify_level: 16`（通知栏+锁屏+横幅+震动+铃声）对红区预警是必需的，静音的哨兵没有意义。

### 7.5 架构：FastAPI 怎么发出这条推送

```
戒指数据 → FastAPI /api/data/hardware-result
                ↓
          alert_engine 判定（年龄分档 + 去抖，见 B5）
                ↓ 触发红区
          写 alerts 表
                ↓
          POST 云函数 URL（HMAC 签名，见下）
                ↓
          uniCloud 云函数 asthma-push
                ↓ uniPush.sendMessage({ push_clientid, category, options, payload })
          个推 + 厂商通道
                ↓
          家长手机通知栏（锁屏 + 横幅 + 铃声）
                ↓ 点击
          uni.onPushMessage type='click' → 跳 /pages/alert/detail?id=xxx
```

**cid 映射**：本产品用**自建 uni-id 体系之外**的账号（我们自己的 `users` 表），所以不能用 `user_id` 维度推送，只能用 `push_clientid` 维度。因此需要：

| 改动 | 说明 |
|---|---|
| **B7（新增）** `devices` 表或新表存 `push_clientid` | `App.uvue onLaunch` 拿到 cid 后调 `POST /api/push/register` 上报，与我方 `user_id` 建映射 |
| **B8（新增）** `POST /api/push/register` | 入参 `{push_clientid, platform}`，需登录态；同一 user 覆盖更新 |
| 登录/token 续期时重新上报 | 官方：cid 3 个月不登录会失效 |

**云函数鉴权**：官方明确 *"需要对云函数 url 增加安全通讯鉴权"*。URL 化后的地址是公网可访问的，裸奔等于任何人都能给你的用户推假预警，**对一个医疗预警产品这是不可接受的**。方案：FastAPI 侧用共享密钥做 HMAC-SHA256 签名（body + 时间戳），云函数内校验，时间戳超 5 分钟拒绝。

### 7.6 第二层：本地通知兜底（保留，不删除）

即使真推送全部打通，仍保留兜底，因为存在真实的失效场景：**用户未授权通知权限、厂商通道被系统冻结、无网络、cid 失效**。

1. 通知权限已补进 `manifest.json`（见 §7.2.2；**注意 uni-app x 不勾 Push 模块，靠摇树**）
2. 用 `uni.getChannelManager().setPushChannel({ channelId:'asthma_alert', importance:4, enableLights:true, enableVibration:true, lockscreenVisibility:1 })` 建**高优先级渠道**
3. app 在线时按用户设定频率拉 `/api/alerts?user_id=&status=待处理`，命中则 `uni.createPushMessage` 建本地通知
4. `force_notification: true` 让在线消息也自动进通知栏

### 7.7 哨兵状态灯（**按方案 b 改写：本轮绿灯不可达**）

首页那行「哨兵」状态**本轮只有两态可达**：

| 状态 | 本轮可达 | 含义 | 判定依据 | 界面文案 |
|---|---|---|---|---|
| **哨兵在岗** ● 绿 | **不可达** | 离线推送链路通 | cid 有效 + 厂商 Device Token 存在 | 本轮不出现 |
| **仅前台值守** ◐ 黄 | **默认态** | 只有在线推送 | 通知权限已授 + 有网络 | 「仅前台值守 · app 被杀或锁屏久置可能收不到预警」 |

**实现约束（写进代码，防止后人误加绿灯）：**

```
状态判定只有两个输入：通知权限 + 网络可达。
没有第三个输入，所以不可能算出绿色。
sentinelState() 的返回值域本轮硬编码为 'amber' | 'gray'。
绿色分支写成显式 TODO 注释加不可达断言，等 §7.3 落地时再打开。
```

**黄态不是「一切正常」，界面必须承认这一点。** 具体三处：

1. 首页哨兵条：黄点 + `仅前台值守` + 副行小字写清失效场景（不用「运行中」这类含糊词）
2. 哨兵条可点，进「报警设置」页顶部有一块**常驻说明区**：为什么现在只有前台值守、

### 11.1 责任口径的文案硬约束（由第 2 条推导，全部页面适用）

**禁止出现的词**：诊断、确诊、病情评估、医疗建议、治疗方案、疗效、医疗级、临床验证、
以及任何把预警结果表述为「结论」的说法。

**必须出现的地方（6 处）**：

| 位置 | 文案 |
|---|---|
| 登录页底部 | 「本应用提供健康参考，不构成医疗建议」 |
| 「关于」页 | 同上，并补一句本应用非医疗器械、不用于疾病诊断或治疗 |
| 预警详情页顶部 | 「以下为设备监测到的数值变化，供参考」 |
| 预警详情第 3 步 | 「**如症状持续请及时就医**」（**不写**「立即就医」，那是医疗指令口径） |
| 行动计划页 | 「本内容由您的医生录入」（区分医生医嘱与本应用的通用安抚措施） |
| 报警设置页阈值区 | 「阈值为参考区间，请以医生意见为准」 |

**术语替换表（编码时逐条照做）**：

| 不要写 | 改写成 |
|---|---|
| 检测结果 / 诊断结果 | 监测数值 |
| 病情加重 | 数值变化 / 超出参考区间 |
| 风险等级 | 关注等级 |
| 立即就医 | 如症状持续请及时就医 |
| 已保护 / 守护中 | 仅前台值守（见 §7.7，只说能力范围内的事） |

> 这条口径同时约束 §4.5 的 signature：「哨兵条」显示的是**设备在不在值守**，
> 不是「孩子有没有事」。前者是本应用能负责的，后者不是。
